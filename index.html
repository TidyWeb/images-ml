00 Start here

Why look at pictures before using them?

A spreadsheet has rows and columns. A picture has a grid of tiny dots called pixels. Each pixel stores a brightness value (and, for colour pictures, colour values too). Before asking a computer to recognise pictures, we should check what is in the collection and how the pictures differ.

01

Look at the collection

Count each label. Look at examples. Notice what stays the same and what changes.

02

Make pictures fit

Real pictures may have different sizes. Resize them so they can be handled together.

03

Keep the groups straight

Put separate pictures aside for learning, practice checks and the final check.

the lesson starts by looking later steps prepare the pictures

What does EDA mean here? Exploratory data analysis means looking through data before modelling. With pictures, we count the labels, look at real examples and check whether the pictures match their labels. We also look for differences in size and in the places that are light or dark. It is the same first question as with a spreadsheet—“What is in this data?”—but pictures need to be inspected as pictures.

Look at the pictures

  1. Can you recognise a bag in each picture?
  2. What stays similar from bag to bag?
  3. What changes, such as shape, angle or brightness?

Picture three photos of the same kind of house. They are framed about the same way, but a roof edge or chimney shifts a little. If we compare the same spot in each picture, some spots stay alike and some change.

1. Three example pictures

Same kind of thing; small differences in the outline.

2. Average picture

Where the outlines land in the same place, they build a darker, steadier line. Shifted parts look softer.

3. Where pictures vary

A simple house drawing helps explain the idea. The course applies the same comparison to same-sized MNIST pictures, such as handwritten zeros. This drawing is an illustration, not a course output.

Now connect the picture to the maths. Take one exact pixel position across all the pictures of zeros. The average image shows the usual brightness at every position. The standard-deviation image shows how much brightness changes at each position. The course calls this its “variability image”. In its greyscale display, lighter areas mean the pictures differed more at those spots. This compares pictures with one another—not different parts of just one picture.

For a tiny example, imagine one pixel has brightness values 40, 40, 40 in three pictures: the average is 40 and there is no spread. If the values are 20, 40, 60, the average is still 40, but the pictures disagree more at that spot.

Same at this spotIf every house has a dark wall line at this position, its average stays dark and the values hardly vary.

Different at this spotIf a roof edge is here in one picture but a little higher in another, the values disagree. The average softens; variability rises.

ImportantThe average is a summary of many pictures. It may look blurred and may not be an actual picture from the collection.

Now the Python words for it

Suppose zero_images contains all the MNIST pictures whose label is 0. Its shape has three parts: how many zero pictures there are, then 28 pixel rows, then 28 pixel columns. The example assumes NumPy and the MNIST arrays have already been loaded.

Pick the zero pictures, then summarise each pixel
zero_mask = (y_train == 0)
zero_images = x_train[zero_mask]

mean_zero = np.mean(zero_images, axis=0)
spread_zero = np.std(zero_images, axis=0)

print("average image:", mean_zero.shape)
print("variability image:", spread_zero.shape)
What this produces average image: (28, 28) variability image: (28, 28)

Translate it

  1. y_train == 0 asks “is this label a zero?” for every picture. The answers are True or False.
  2. x_train[zero_mask] keeps only pictures whose answer was True.
  3. np.mean(..., axis=0) averages the brightness of each matching pixel. axis=0 means compare down the stack of pictures; the count of pictures disappears and the 28-by-28 grid remains.
  4. np.std(..., axis=0) measures how much brightness differs at each matching pixel from picture to picture. That measure of spread is called standard deviation.

The course wraps these steps in image_avg_and_variability_data_as_array(). It repeats them for every label, from 0 to 9, and displays an average beside a variability picture for each digit.

Compare two labels

To compare two kinds of picture, first find the average picture for each label. Then subtract the second average from the first, one pixel at a time. The result shows where their average pixel values differ.

What the function displays 1. Difference: average 8 minus average 2 2. Average image for label 8 3. Average image for label 2 Here, x_train and y_train are the MNIST digit data.

How to read the difference

At a pixel where both averages match, their difference is zero. A positive result means the average for 8 is brighter there; a negative result means the average for 2 is brighter. The lesson's grey display makes “where do they differ?” easier to see than the direction of that difference.

For the Fashion-MNIST practice: use x_practice and y_practice together. In that dataset, label 8 is a bag and label 2 is a pullover. The numbers stay the same, but the pictures they name depend on which dataset is in X and y.

Keep the dataset and labels together

If you use x_train with y_train, you are studying digits. If you use x_practice with y_practice, you are studying clothes. Do not mix the image array from one dataset with labels from the other.

Open the supplied archive and list its folders
from zipfile import ZipFile

with ZipFile("Chess.zip", "r") as chessZip:
    chessZip.extractall()

my_data_dir = "Chess"

import os
labels = os.listdir(my_data_dir)
print(labels)
What is happening ZipFile opens the archive named Chess.zip; extractall() unpacks it in the notebook's current folder. os.listdir("Chess") asks Python to list the items in that one folder. import os supplies folder tools. It does not download data or search your whole computer.

Why there are two loops

  1. The outside loop chooses a dataset folder.
  2. Inside it, for label in labels visits Bishop, then King, then Knight.
  3. Each visit counts the picture files in that one category folder and records its name and count.
  4. So one Chess folder produces three rows in the little summary table. If there were two dataset folders, the same three checks would happen for each one.

Why resize the pictures?

One Chess picture may be wide and another tall. A single NumPy array needs every picture to have the same height and width, so the helper resizes them before putting them together. Here new_size gives the target height and width; after resizing, all pictures have the same pixel-grid shape.

Ask the supplied helper for a small sample

    images_amount=2,
)
What comes back X contains the resized picture arrays. y contains their labels: Bishop, King or Knight. The lesson loads just two pictures per label to keep the example small. That is a demonstration sample, not the full dataset.

Files become arrays

  1. Start with separate picture files in labelled folders.
  2. Resize them so every picture has matching dimensions.
  3. Put the pixel values together in X.
  4. Put the matching folder labels in y.

04 Dataset splits

Keep the learning pictures and final check separate

Think of the three groups like school work: the model gets study material, practice checks help you make choices, and a final set stays closed until those choices are finished. Each picture goes into one group only.

TrainStudy material: the model uses these pictures to learn.Choices are still being developed.
ValidationPractice check: use these pictures to compare settings and make development choices.It can be checked while improving the model.
TestFinal check: keep these pictures aside until the choices are settled.The final estimate comes from pictures not used during those choices.

The Chess example divides the pictures in these proportions. The bar widths match the percentages.

Why do the names feel backwards? For the school analogy, validation is the mock exam: you can check the result and use it to improve your approach. Test is the sealed final exam: keep it aside until the choices are settled. These are machine-learning role names, not the everyday meanings of “test” and “validation”.

Before: Chess/Bishop, Chess/King, Chess/Knight ↓ move each picture into exactly one group After: Chess/train, Chess/validation, Chess/test Each destination still has Bishop, King and Knight folders

What the three numbers mean 65% of the pictures move to Train. 15% move to Validation. 20% move to Test. Together, the percentages add up to 100%. Each file is moved into one destination.

What the helper does

  1. It handles one label folder at a time.
  2. It shuffles the picture filenames so their order is not fixed.
  3. It moves the chosen files into the Train, Validation or Test folder.
  4. It keeps Bishop, King and Knight subfolders under each group.
COVID example · make Validation from the existing Train group

Meaning of 0.8 80% of the existing Train pictures stay in Train. 20% move from Train to Validation. The Test group is left as it was.

Translate the ratio

  1. The function starts with the Train folder.
  2. train_set_ratio=0.8 means 80% remains there.
  3. The leftover 20% becomes Validation; Test does not take part in this operation.
05 Retrieve

Say it back in your own words

Try to answer each question before opening its explanation. These checks test the connections between concepts, not just whether the words look familiar.

What is the relationship between X and y?

X contains input images. y contains matching labels. The same index connects them.

Why does axis=0 leave an image-shaped result?

The first dimension is the collection of images. Comparing across that dimension leaves one value for each matching pixel position.

Why does a folder name matter?

The folder name is used as the label. Chess/Bishop tells the loader what class those files belong to.

What is the difference between validation and test?

Validation is consulted while choices are still being made. Test is held back for the final estimate, so it remains a more honest check of the finished approach.

What happens if you pass x_train to the Fashion-MNIST exercise?

Python may run it without an error, but it will show handwritten digits, not clothing. Use the matching Fashion-MNIST arrays x_practice and y_practice.
